Search Intelligence Capstone — CTR / Engagement Opportunity Scoring

Search Performance Signals for Content Prioritization Using a Decision Tree Model

FlyRank ML Internship Dataset · March 2026 release · Decision-support research

This study investigates whether search performance signals can be used to identify content pages that should be reviewed first.

A Decision Tree classifier was trained on search performance metrics from the FlyRank ML Internship dataset and compared against a simple rule-based baseline, evaluated on the same held-out split. The review-candidate label is defined relative to the sample (bottom quartile of CTR among pages that actually received search impressions), rather than against a fixed universal CTR benchmark — see Section 3.1.

The Decision Tree achieved an accuracy of 71.01% (macro-F1 0.6044) on the held-out split, compared with 52.26% (macro-F1 0.4526) for the rule-based baseline evaluated on the same split. A grouped-by-page validation split and 5-fold cross-validation both gave consistent results.

The model is intended for decision-support only and should be combined with human review before any content action is taken.

01

Introduction

Content teams often manage thousands of pages and cannot manually review every one of them.

Search performance metrics — such as average search position, pageviews, and scroll behavior — provide signals that may help prioritize which pages deserve attention first.

This project investigates whether those signals can be used to identify pages that should be reviewed before others.

The goal is not to automate content decisions but to support human reviewers with a ranked, interpretable recommendation list.

02

Data

This project uses the FlyRank ML Internship dataset, drawn from the fact_content_daily_performance table of the March 2026 (month=2026-03) warehouse release, accessed via DuckDB over the hosted Hugging Face warehouse.

Date window & sampling

The March 2026 partition of the warehouse. 100,000 rows were sampled from this partition. Two row-level filters were then applied before modeling: gsc_data_available == True (the row must have real measured GSC data for that day, not just belong to a client whose account is connected) and gsc_impressions > 0 (the page must have actually appeared in search results). After both filters, 39,751 rows (39.8%) remained for modeling.

Selected features

  • gsc_avg_position — average search ranking position
  • ga4_pageviews — pageviews from analytics
  • ga4_sessions — sessions from analytics
  • sessions_organic — organic-search sessions
  • scroll_events — scroll-depth engagement events

Target label source

CTR is computed from gsc_clicks / gsc_impressions, restricted to the filtered rows above. CTR itself is not used as a model feature, only to build the label.

A notable finding surfaced directly from the data: 85.71% of visible pages (impressions > 0) received exactly zero clicks. This is reported here plainly because it shaped the labeling approach in Section 3.1 — a fixed universal CTR threshold (e.g. "CTR < 5%") would have flagged nearly every page in this sample and produced a meaningless, degenerate label.

Exclusions and why

  • Client names, domains, page URLs, and private search queries are excluded from this paper and the underlying notebooks, to keep the work public-safe.
  • Rows without real GSC data for that day, and rows with zero search impressions, are excluded from modeling rather than zero-filled — treating "no data" as "zero performance" would silently mislabel untracked pages.
  • Within the remaining rows, missing values in the selected features are filled with zero — a page can genuinely have zero pageviews or scroll events and still be a valid, in-scope row.

03

Methodology

3.1 — Target label construction

The review-candidate label flags the bottom quartile of CTR within the filtered sample — a relative, dataset-driven cutoff — rather than a fixed universal benchmark. An earlier fixed 5% cutoff was tried first and rejected: it flagged ~99% of the sample, which doesn't separate anything, it just describes the dataset. Because the zero-CTR tie group (85.71%) is itself larger than the 25% target, the flagged share came out larger than 25% by construction — the full tie group at the cutoff is included rather than arbitrarily split.

3.2 — Baseline vs. Decision Tree

The baseline is a single rule on gsc_avg_position alone (pages positioned worse than the sample median — 7.10 — are flagged). The Decision Tree (max depth 6, class_weight="balanced") uses all five features jointly. Both are scored on an identical 80/20 held-out split, stratified by label.

3.3 — Grouped validation split

A single random split can overstate performance if the same page appears in both train and test. This was re-checked with a split grouped by content_hash_id (38,797 unique pages), so all rows for a given page land entirely in train or entirely in test. The grouped-split result (75.65% accuracy, 0.6279 macro-F1) was close to the random-split result, indicating the random split was not meaningfully inflated by same-page leakage.

3.3b — Cross-validated stability check

Because the smaller class is still a minority even after filtering, a single split can be noisy. 5-fold stratified cross-validation gave a macro-F1 of 0.5988 ± 0.0152 — consistent with, and about as stable as, the single-split estimate.

3.4 — Leakage audit

The CTR column (and its source clicks/impressions columns) were confirmed absent from the feature set. Correlations between each feature and the label were checked for any suspiciously high (>0.95) value that would suggest near-restatement of the target — none were found; the strongest was ga4_sessions at −0.29.

04

Results

The Decision Tree achieved an accuracy of 71.01% (macro-F1 0.6044) on the random-split test set, compared with an accuracy of 52.26% (macro-F1 0.4526) for the rule-based baseline on the same split. Across 5-fold stratified cross-validation, the Decision Tree's macro-F1 was 0.5988 ± 0.0152. Under the grouped validation split, the Decision Tree achieved 75.65% accuracy / 0.6279 macro-F1.

The Decision Tree's macro-F1 (0.60) is meaningfully above the baseline's (0.45) and stable across cross-validation folds — the model is genuinely separating the two classes rather than just predicting the majority. But a macro-F1 of ~0.60 is still modest: this is decision-support evidence, not a precise or highly confident classifier.

Grey = baseline, teal = Decision Tree. Grouped macro-F1 (0.628) is annotated on the grouped-accuracy pair above for space.

Feature importance

sessions_organic and gsc_avg_position drive nearly all of the tree's decisions; the other three features contribute marginally.

05

Limitations & honest framing

  • Decision-support only. This model is not intended to trigger automated content changes.
  • Single-month dataset. The March 2026 release captures one point in time; no seasonality is modeled.
  • Relative, not absolute. The label is defined against this sample's own CTR distribution, not a universal CTR benchmark — the finding is about relative under-performance within this dataset.
  • Observational, not causal. Associations between features and the label do not establish that changing a feature would change CTR.
  • No business context. The model has no information on recent edits, business priority, or campaign timing.
  • Modest separation. A macro-F1 of ~0.60 is a real, stable improvement over the baseline, not a strong or highly confident classifier — human review remains required.
